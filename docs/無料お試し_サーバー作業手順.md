## 1. タスクを登録する

EC2 に RDP で入り、**管理者権限のコマンドプロンプト**で実行する。
`<CRON_SECRET>` は実際の値に置き換える（山カッコは消す）。

```bat
schtasks /create /tn "felikko-trial-capture" /sc daily /st 09:20 /ru rpa_admin /tr "curl -s -X POST https://www.felikko.com/api/trials/capture -H \"Content-Type: application/json\" -H \"Authorization: Bearer <CRON_SECRET>\" -d \"{}\""
```

- SEO Rank Watch が 09:10 に動いているので、重ならないよう 09:20 にしている
- `/ru rpa_admin` は SEO タスクと同じ実行ユーザー

### 注意（ハマりどころ）

**`Content-Type: application/json` を必ず付ける。** 付けないと Astro の CSRF 保護が
フォーム送信とみなし、`403 Cross-site POST form submissions are forbidden` になる。
本番で実測済み。

## 2. 動作確認

登録したタスクを手動で1回走らせる。

```bat
schtasks /run /tn "felikko-trial-capture"
schtasks /query /tn "felikko-trial-capture" /fo LIST /v | findstr /i "前回の結果 前回の実行"
```

コマンドプロンプトから直接叩いて応答を見るのが確実。

```bat
curl -s -X POST https://www.felikko.com/api/trials/capture -H "Content-Type: application/json" -H "Authorization: Bearer <CRON_SECRET>" -d "{}"
```

**期待する応答**

```json
{"checked":0,"captured":0,"released":0,"expired":0,"failed":0}
```

| 応答 | 意味 |
|---|---|
| `{"checked":0,...}` | 正常。対象0件（お試し注文がまだ無いだけ） |
| `{"error":"unauthorized"}` | `CRON_SECRET` が違う |
| `403 Cross-site POST...` | `Content-Type` が無い |

## なぜ先に必要か（重要）

タスクを登録しないと、**誰も課金の合図を出しません**。

```
購入 → 与信確保（請求なし） → お試し期間終了 → [誰も動かない] → 30日でオーソリ失効 → 請求権が消える
```

お試し期間が終わっても自動で決済されず、そのまま放置すると **30日でオーソリが失効して
請求できなくなります**。つまり商品を無料で配ることになります。

ただし **オーソリは30日間有効**なので、仮に数日タスクの登録が遅れても、
登録後の初回実行で「期限を過ぎた注文」をまとめてキャプチャーします。
**30日以内に登録すれば取りはぐれません。**

## 日々の監視

毎日の実行結果で見るべき数値。

| キー | 意味 | 対応 |
|---|---|---|
| `captured` | 決済確定した件数 | 正常 |
| `released` | 返品で与信解放した件数 | 正常 |
| `failed` | 4回失敗して手動対応待ち | Stripe で確認 |
| `expired` | **オーソリ失効。請求できていない** | 要調査。タスクが止まっていた可能性 |

`expired` が出たら、タスクが数日以上止まっていたことを意味する。
Stripe ダッシュボードの「未キャプチャー」一覧と突き合わせること。

## 返品を受けたとき

`POST /api/trials/release` に `{ orderId, accessToken }` を渡すと与信を解放する。
まだ請求していないので **返金ではなく保留の解放**。返金手数料もチャージバックのリスクもない。
