# SEO Rank Watch

Target: `https://www.felikko.com/`. Repository: `free-market`.
The user's workflow is authoritative: one keyword per run, seven days observing, then measured review. Do not promise first place. This skill runs one cycle; installing it does not start a scheduler.

## Persistent data

- `data/seo/config.json`: property, exact origin, country/device/search scope and reporting timezone.
- `watchwords.json`: array of `{keyword,targetPath,priority}`. Priority: high / normal / low.
- `rank-history.json`: append-only observation snapshots. Never edit or remove existing observations, including to correct an error; append a corrected observation instead.
- `improvement-log.json`: keyword/page status active / observing / achieved, action history, review history, nextReviewDate.
- `analytics-history.json`: append-only GA4 usage reports using the same external service account. GA4 supports analysis; it never replaces GSC rankings. Missing data or API failure is not zero sales. Purchase events are not verified orders. Only public product paths are retained.

Do not seed fictitious rank data or force a keyword into an empty watchlist. GSC discovery can supply candidates. Never interpret null rank and zero impressions as proof of non-indexing.

## One cycle

1. Check repo status, instructions and existing changes. Stop if another SEO cycle holds `.seo-rank-watch.lock`. Do not touch unrelated user work.
2. Measure:
   ```sh
   node .claude/skills/seo-rank-watch/scripts/fetch_gsc_ranks.mjs --repo <REPO_PATH> --append
   node .claude/skills/seo-rank-watch/scripts/fetch_gsc_ranks.mjs --repo <REPO_PATH> --days 7 --append
   ```
   Credentials are read from `GSC_CREDENTIALS_FILE` or `GOOGLE_APPLICATION_CREDENTIALS`; a short-lived `GSC_ACCESS_TOKEN` also works. Read `references/setup.md` when configuring access. Never print tokens or credential JSON. Authentication failure is not zero impressions; no fabricated snapshots may be appended on failure.
3. Run `seo_watch.mjs --repo <REPO_PATH> review`, then `... plan`. Reviews use only seven-day GSC windows with the same scope. If the latest finalized seven-day window overlaps the improvement date, wait for complete post-change data. Do not change to active on missing data. Rank 1 becomes achieved; improved but not 1 or no improvement becomes active. Log outcomes, including insufficient data. Never compare a 28-day baseline to a seven-day result.
4. Choose one candidate in this order: tracked rank 2–10 with impressions (closest to first); rank 11–20 with high impressions; other previously reviewed active keywords; high-priority null rank; promising untracked GSC query. Exclude observing and achieved keywords. Also exclude a page already observing under another keyword. No candidate means report only.
5. Before editing, state in 1–2 sentences who is searching and what they need. Use WebSearch to examine the current top 1–3 relevant results, record URLs and the observed gap against the target page. WebSearch order is approximate, not measured Google rank. Never scrape Google SERPs. For an untracked discovery candidate, first add its exact keyword/path to watchwords.json, then fetch a seven-day snapshot again so the exact-query baseline exists even with zero impressions. Do not edit or publish until that baseline succeeds. When GSC is unavailable, a manual WebSearch assessment is permitted, but cannot be used by the recorder as a GSC measurement or to mark achieved.
6. Implement one useful change addressing that gap: title, description, intro, FAQ, factual content or a relevant internal link. Do not invent product attributes, reviews, sales, certifications or shipping promises. Product pages are generated by `src/pages/products/[id].astro` using Supabase: editing a shared template can affect every product; use a target-specific change instead. Do not change noindex, canonical/URL routing or large page structure without the user's explicit approval. Do not send email/Discord or post to social media.
7. Validate the specific change. Publish through the existing repo workflow only within user authorization. A draft or local commit is NOT a deployed improvement. Record `deployedAt`, deployment URL/commit evidence and the actual change only after publication is confirmed. Take a seven-day GSC baseline before editing.
   ```sh
   node .claude/skills/seo-rank-watch/scripts/seo_watch.mjs --repo <REPO_PATH> record --input <ACTION_JSON>
   ```
   ACTION_JSON fields: keyword, targetPath, needs, gap, done, method, sources (1–3 HTTPS URLs), deployedAt (ISO timestamp), deploymentEvidence, runId (the same identifier throughout this cycle). No secrets. The recorder requires an eligible candidate and a pre-change seven-day baseline, enforces one action per runId, and sets observing until deployedAt + 7 full days.
8. Commit only the intended page change and `data/seo/*.json`. Do not commit credentials, runtime caches, report artifacts or unrelated files. Do not rewrite rank-history. A daily scheduled run should skip edits during observing, even under another keyword for that URL.

## Report

Report large comparable position rises/falls; due review results; the chosen keyword and reason; inferred intent; actual changes and publication evidence; observing keywords and nextReviewDate. If no GSC access, no candidate or no complete post-change window, say so and do not claim improvement. Achieved entries are monitored only.
